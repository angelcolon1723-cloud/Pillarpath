════════════════════════════════════════════════════════════════════════════

1️⃣  CHOOSE YOUR DEPLOYMENT METHOD
    
    Option A: Docker (Recommended)
      Requirements: Docker Desktop
      Time: 5 minutes
      Best for: Dev, staging, or small scale
      
    Option B: Vercel (Best for Production)
      Requirements: GitHub account
      Time: 5 minutes
      Best for: Production, auto-scaling
      
    Option C: Local Node.js
      Requirements: Node 18+, PostgreSQL
      Time: 10 minutes
      Best for: Development only

2️⃣  RUN THE QUICK START SCRIPT

    cd pillarpath-work
    bash ../QUICK-START.sh
    
    • Select your deployment method (1, 2, or 3)
    • Script handles: env setup, migrations, dependencies
    • Automatic! Follow on-screen prompts

3️⃣  VERIFY DEPLOYMENT

    • App should open at http://localhost:8080 (local)
    • Or your-domain.com (production)
    • Create test account
    • Draw something in the studio
    • Check that units display correctly

🔑 CRITICAL SECRETS (Store Safely!)
════════════════════════════════════════════════════════════════════════════

Generate these BEFORE deploying:

JWT_SECRET:
  openssl rand -base64 32
  Min 32 characters for production

DATABASE_URL:
  postgresql://user:password@host:5432/pillarpath
  Get from your database provider

STRIPE_SECRET_KEY:
  sk_test_... or sk_live_...
  Get from stripe.com/dashboard

STRIPE_PUBLISHABLE_KEY:
  pk_test_... or pk_live_...
  Get from stripe.com/dashboard

Store these in a password manager. Never commit to git!

🆘 NEED HELP?
════════════════════════════════════════════════════════════════════════════

Issue: Port 8080 already in use?
  → Run: lsof -i :8080 | grep LISTEN | awk '{print $2}' | xargs kill -9

Issue: Cannot connect to database?
  → Check: echo $DATABASE_URL
  → Test:  psql $DATABASE_URL -c "SELECT 1;"

Issue: Login not working / session not persisting?
  → Check: Browser console for auth.session cookie
  → Reset: Delete all cookies and sign in again

Issue: Something broken?
  → See: RC6-TROUBLESHOOTING.md (25+ solutions)
  → Or:  docker-compose logs -f (view error logs)
